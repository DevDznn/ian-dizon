# Ian Dizon — Portfolio

A one-page portfolio for Ian Dizon, WordPress Developer. It is built with HTML5, CSS3, Tailwind CSS and vanilla JavaScript. It does not use any framework or animation library.

```
PORTFOLIO/
├── index.html              ← all content (projects, experience, contact)
├── css/
│   ├── styles.css          ← hand-written: theme tokens, components, motion
│   ├── tailwind.css        ← GENERATED by Tailwind (don't edit by hand)
│   └── tailwind.input.css  ← Tailwind source
├── js/
│   └── main.js             ← theme, mobile menu, filters, nav state, typed role, scroll reveals
├── assets/
│   ├── images/             ← project screenshots (.webp) + og-image.jpg
│   └── icons/favicon.svg
├── tailwind.config.js
└── package.json            ← only used to rebuild tailwind.css
```

## Running it

The site is static. You can open `index.html` directly, or serve the folder with any static server, for example `npx serve .`. Then deploy the folder to Vercel, Netlify or GitHub Pages as it is.

## Why Tailwind is compiled, not loaded from the CDN

The Tailwind Play CDN is a JavaScript file. If it were used, the page would show up unstyled for anyone with JavaScript turned off. Instead, the utilities are compiled into `css/tailwind.css`, so the whole site renders and stays readable without JavaScript.

**Whenever you add or change Tailwind classes in `index.html`, rebuild the CSS:**

```bash
npm install          # first time only
npm run build:css    # or: npm run watch:css while editing
```

If you'd rather use the CDN while prototyping, you can do this instead:
1. Swap `<link rel="stylesheet" href="css/tailwind.css">` for `<script src="https://cdn.tailwindcss.com"></script>`.
2. Paste the `theme.extend` block from `tailwind.config.js` into `tailwind.config`.

## Theme behaviour

- On the first visit, the theme follows the operating system's `prefers-color-scheme` setting.
- Clicking the toggle saves the choice in `localStorage['theme']`.
- A small inline script in `<head>` applies the theme before the first paint, so the wrong theme never flashes.
- If storage is blocked, the toggle still works for the current page view.
- Without JavaScript, the CSS falls back to the operating system's setting and the toggle is hidden.
- Colours are CSS variables in `css/styles.css` (`:root` and `[data-theme="dark"]`). Tailwind colour names such as `text-muted` and `bg-paper` point to those variables.
- `prefers-reduced-motion` turns off the hover zoom, the filter fade, the status pulse, the hero entrance, the typed role (it stays on "WordPress Developer"), the scroll reveals and smooth scrolling.

## Before deploying

- Set `og:url` and change `og:image` to an absolute URL on your final domain.
- Re-check that the live links still point at the right sites.

## Design

Editorial layout: condensed **Archivo** display type (pulled to 66% width), **Geist** for body text and **Geist Mono** for labels, on a warm bone / near-black palette with one vermilion accent. Tokens are CSS variables at the top of `css/styles.css`.

## Motion

All motion is CSS transitions/keyframes plus a little vanilla JS (no libraries). `prefers-reduced-motion` turns all of it off.

- **Hero**: each word of the name rises out of a mask; the "WP" badge's ring text rotates slowly.
- **Ticker**: a slow marquee, paused on hover.
- **Nav indicator**: a pill slides to the link of the section in view (`[data-nav-indicator]`).
- **Manifesto**: highlight bars sweep in when the band scrolls into view.
- **Work rail**: native horizontal scroll with snap points; prev/next buttons, counter, progress bar and mouse drag are added by `main.js`. Without JS it still scrolls.
- **Process**: the dashed connector draws in when the section is in view.
- **Scroll reveals**: add `data-reveal` to fade an element in, or `data-reveal-children` to fade its direct children in with a short stagger. Elements already on screen at load are never hidden.
